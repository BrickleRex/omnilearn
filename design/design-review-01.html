Decision 01

The shape of the app

One screen owns your attention at a time. A project is a goal ("tokenizer from scratch"); it breaks into milestones (train BPE → encode → decode), and every milestone runs the same five-beat loop:

1

Pick

Project → milestone. Plain list, zero ceremony.

2

Calibrate

2–3 min. The instructor probes what you already know — you can answer, or just say "I know this, test me".

3

Primer

Reading only for the gaps. Each concept ends in one check question. No text walls.

4

Build

The editor. You type everything. Hints and ghost lines on demand; a watcher decides when to nudge.

5

Reflect

Run it, compare against a reference, log what tripped you up. Feeds the next calibration.

Library ├─ Attention from scratch numpy │ ├─ scaled dot-product attention done │ ├─ multi-head + projections ● current │ └─ causal masking ├─ Tokenizer python │ ├─ BPE training loop │ └─ encode / decode └─ Inference engine not from scratch └─ KV-cache on top of my MHSA

How the instructor decides "enough"

  • Every milestone carries a short, visible concept list (for MHSA: dot products as similarity, scaling, softmax, weighted sums, heads). You can see and veto it.
  • A concept is cleared one of three ways: you evidenced it in calibration, you passed its one check question after reading, or you demonstrated it in code from a previous milestone.
  • All concepts cleared → primer ends itself and drops you in the editor. It never pads. If you flounder later, the watcher can reopen exactly one concept — not the whole lesson.

The watcher (the open question you raised). It reads your diffs in the background and holds one of three postures — wrong code is allowed to run; that's how you learn:

Quiet

Default. You're wrong in a recoverable way, or productively struggling. It says nothing — a mistake you find yourself is the lesson.

Nudge

Only when you're heading down a rabbit hole: an error that contradicts a cleared concept, or ~10 min circling the same spot. A small amber dot appears in the gutter. It never interrupts — you tap it (or ⌥H) to read one or two kid-simple lines.

Explore

You toggle it (⌥E). "I'm breaking things on purpose." Watcher goes fully silent, and your diffs get marked as experiments, not mistakes.

Default hotkeys (all rebindable): ⌃Space next-step hint · ⌃⇧Space ghost code line · ⌃` terminal · ⌥E explore · ⌘↵ run file.

Decision 03

Where the terminal lives

Your constraint: the VS Code bottom dock steals vertical space and costs clicks both ways. Five answers, all one-key (⌃`), all animated with their real transitions. Demos use a neutral skin — this choice is independent of 02.

T1The Veil

Terminal is a translucent layer that slides over the code. You never lose a single line of editor height — the code stays ghosted underneath, and one key dismisses it.

mhsa.py⌃` toggles
$ python mhsa.py
scores  (4, 4)
weights rows sum → 1.0000
out (4, 8) ✓ matches reference
⌃`
Wins: zero standing cost, fastest in/out. Cost: can't read code and output at the same instant.
T2The Rail

A narrow always-on output column on the right. Code keeps full height; output streams beside it and glows when something new lands. Focus it only when you need to type into it.

mhsa.pyoutput rail · live
$ run
scores (4,4)
sum 1.0000
out (4,8)
✓ ref ok
Wins: code + output visible together, no toggling ever. Cost: ~100px of width, wraps long lines.
T3The Pulse

At rest: a one-line tail, like a status bar that happens to be your shell. On run, it springs up, shows the result, and folds itself away after a beat. The terminal manages its own presence.

mhsa.pyauto-collapse 4s
$ … out (4, 8) ✓
$ python mhsa.py
scores (4, 4) · weights rows sum → 1.0000
out (4, 8) ✓ matches reference
⌘↵ run
Wins: zero clicks either direction — it appears when relevant, leaves when not. Cost: motion you don't control; pin-open needs a key.
T4The Lens

Notebook logic in a real file: output materializes inline, right under the code that produced it, then collapses to a one-word chip. Results live next to their cause, not in a distant panel.

T5The Loupe

A floating glass mini-terminal, docked to a corner, semi-transparent until output arrives. Drag it anywhere; it never reflows your code.

Decision 04

Hints & the ghost line

Two separate gestures. ⌃Space gives a text hint — the next precise step, one or two lines, explained like you're fifteen (press again for the composite step). ⌃⇧Space reveals the ghost line — actual code, visually quarantined, and Tab will never accept it. First: four ways the text hint can arrive.

H1Whisper

The hint breathes in directly above your cursor line, italic and dim, and fades the moment you start typing. Guidance at the point of doubt, nowhere else.

mhsa.py⌃Space
divide scores by √dk — big dots make softmax spiky
⌃Space
Wins: zero eye travel, self-cleaning. Cost: briefly pushes code down one line (or overlays it).
H2Margin Note

A tutor's annotation in a reserved right margin, tied to your line by a hairline thread. Hints accumulate quietly; the code column itself is never touched.

mhsa.py⌃Space
Scale by √dk here — otherwise softmax goes spiky and one token hogs all the attention.
Wins: code untouched, hints have a home, re-readable. Cost: permanent margin = fewer columns (pairs badly with Zen, well with Field Notes).
H3Compass

A slim strip above the editor always names where you are — step pips plus a five-word heading. ⌃Space unfolds one sentence of detail beneath it. Orientation is ambient; explanation is on demand.

mhsa.pystep 3 / 7
turn scores into weights
Apply softmax along the last axis — each row becomes shares that sum to 1.
⌃Space
Wins: you always know where you are in the plan; least "AI popping up". Cost: a persistent strip; steps must stay honest as you diverge.
H4Footlight

One quiet line at the very bottom where the hint types itself out. The amber lamp says "I have something" (that's also the watcher's nudge channel) — the text only appears when you ask.

mhsa.py⌃Space
Next: apply softmax — each row becomes shares.
Wins: a single stable place for all guidance, easy to ignore. Cost: far from the cursor; one line caps hint length (maybe a feature).

Decision 05

The primer, four ways

The reading that happens before code — sized by calibration, ended by the "enough" rule from 01. Four formats for the same MHSA material:

P1Deck

One idea per card, a diagram on most, a check question at the end of each concept. Swipe through; skip a card by answering its check early.

Check yourself

Q is (4, 64) and K is (4, 64). What's the shape of Q·Kᵀ — and why does that shape make sense?

a) (64, 64)   b) (4, 4) ✓   c) (4, 64)
Why √dk?

Bigger vectors → bigger dot products → softmax collapses onto one token. Dividing by √dk keeps the contest fair.

scores / √64 → gentle weights
Attention is a weighted average

Each token asks "who's relevant to me?", scores everyone, then averages their values by those scores.

out = weights · V
Wins: enforced concision, progress is visible, phone-friendly. Cost: chops flowing arguments into fragments.
P2Scroll Story

One continuous piece with a pinned diagram that transforms as you scroll — the animate.com / GSAP scrollytelling grammar spent on explanation, not decoration.

1 · Score every pairQ·Kᵀ asks, for each token: how relevant is everyone else to me?
2 · Make them sharesSoftmax turns raw scores into positive weights that sum to one.
3 · Blend the valuesEach output is a weighted mix of V — attention is just averaging, done carefully.
Wins: the strongest "aha" delivery; ideas connect. Cost: heaviest to author per lesson; skimming is harder.
P3Atlas

The milestone's concepts as a map. Rings show mastery from calibration; you read in any order; the pulsing node is the instructor's suggestion. "Enough" is visible — the map is full.

Wins: non-linear, mastery and "enough" are literally visible, doubles as the calibration UI. Cost: maps get silly for small lessons; needs a reader panel anyway.
P4Socratic

Calibration and primer are one conversation: it asks, you answer in your own words, it teaches only into the gaps, then hands you a plan of what it skipped and why.
